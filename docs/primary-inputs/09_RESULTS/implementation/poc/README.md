# GitHub-Native AI Documentation System — Proof of Concept

Executable PoC for the architecture defined in `../03_solution/` (ARCHITECTURE-SPINE,
ai_architecture, content_architecture): **docs-as-code, static-first, AI-in-CI**.
One repository is the system of record, the published site is a static build
artifact, and AI writes only through pull requests — never in the serving path.

## The five scenarios this demonstrates

| # | Scenario | Files | Command |
| --- | --- | --- | --- |
| 1 | Two structurally separated content planes (canonical `/docs`, generated `/views`) | `docusaurus.config.ts` (two `plugin-content-docs` instances), `docs/source/**`, `docs/generated/**` | `npm run build` |
| 2 | Provenance + mechanical drift detection via content hashes | `generation.source_documents[].content_hash` in `docs/generated/**`, `schemas/document.schema.json` | `python3 scripts/validate_docs.py`, `python3 scripts/detect_changes.py --all` |
| 3 | Contract-driven, evidence-bounded generation with prompt-injection armor | `contracts/*.yaml`, `prompts/*.md`, `scripts/generate_page.py` | `python3 scripts/generate_page.py --contract GenerateRecruiterPage --target architecture-system-overview --dry-run` |
| 4 | Thin provider abstraction with config routing and privacy hard-pinning | `ai/*.py`, `ai.config.yaml`, `.env.example` | exercised by the dry run above (chain selection needs zero keys) |
| 5 | Build-time career views: recruiter page with `<EvidenceLink>`, `<InterviewPrep>` rendering committed JSON | `docs/generated/recruiter/project-overview.mdx`, `docs/generated/interview/*`, `src/components/**`, `schemas/interview.schema.json` | `npm run build`, then visit `/views/...` |

## Quickstart

```bash
npm install --no-audit --no-fund
npm run build                      # builds en + hu; hu falls back to English
npm run serve                      # serve build/ locally

pip install pyyaml jsonschema      # jsonschema optional — script has a fallback
python3 scripts/validate_docs.py   # frontmatter schema + plane integrity + hashes
python3 scripts/detect_changes.py --all
python3 scripts/generate_page.py --contract GenerateRecruiterPage \
  --target architecture-system-overview --dry-run   # works with ZERO api keys
```

Live generation additionally needs provider keys and model env vars — see
`.env.example`. **Never commit a key.** Model identifiers are env values referenced
from `ai.config.yaml`; nothing in code or config names a model.

## Version and dependency notes

- **Node:** validated on Node 22 with **Docusaurus 3.10.2**, whose published engine
  range is `node >=20.0` — no version pin/downgrade was needed. (The design docs
  mention Node >= 24.14 as the seed toolchain; 3.10.2 does not actually require it.)
- **Search:** the design (AD-13) calls for `@easyops-cn/docusaurus-search-local` in
  production. It is deliberately **omitted from the PoC** to keep the dependency
  tree small and the build deterministic; adding it is a config-only change.
- **Mermaid:** `@docusaurus/theme-mermaid@3.10.2` declares `@mermaid-js/layout-elk`
  as a required peer dependency — it is in `package.json` because the client bundle
  fails to resolve without it (discovered during validation).
- **`future.faster` / Rspack:** AD-2 mentions the faster flags; the PoC uses the
  default webpack build to avoid the extra `@docusaurus/faster` dependency.
- The generated docs plugin uses autogenerated sidebars for both planes.

## Honest limitations

- No live generation run is included: `docs/generated/**` content was authored to
  be byte-exact what the pipeline would emit (real sha256 provenance hashes,
  contract/prompt versions, `model: set-by-ai-config` placeholder) and the pipeline
  is demonstrated in `--dry-run` mode, so the PoC is fully verifiable offline.
- The `hu` locale builds and serves entirely via English fallback — no actual
  Hungarian translations are shipped.
- The GitHub workflows are syntactically valid and least-privilege, but the PR
  push/create commands in `docs-generate.yml` are commented placeholders since the
  PoC directory is not a GitHub repository.
- Quality gates listed in contracts are enforced to the extent the PoC implements
  them (frontmatter schema, hash currency, build/link check); the named-entity
  evidence check and link allowlist are declared but not implemented here.
- `GenerateQuestionPage` / `UpdateMermaidDiagram` etc. exist as contracts only;
  only the recruiter and interview outputs are materialized.

## Layout

```
docusaurus.config.ts        # two docs-plugin instances, mermaid, i18n en+hu, onBrokenLinks: throw
docs/source/                # CANONICAL plane (human-owned)     -> /docs
docs/generated/             # GENERATED plane (bot-via-PR only) -> /views
docs/diagrams/              # canonical .mmd sources, compiled in CI
src/components/             # InterviewPrep, EvidenceLink (registered globally via src/theme/MDXComponents.tsx)
ai/                         # provider Protocol + 4 HTTP adapters + config router
contracts/  prompts/        # task contracts and versioned prompt templates
schemas/                    # document (frontmatter) + interview JSON schemas
scripts/                    # validate_docs, detect_changes, generate_page
.github/workflows/          # docs-validate (PR gate), docs-generate (dispatch)
VALIDATION_NOTES.md         # every validation command actually executed + results
```
